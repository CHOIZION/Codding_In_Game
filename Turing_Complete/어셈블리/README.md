## 어셈블리 프로그래밍

### 개요

어셈블리 언어의 목적은 컴퓨터가 실행하는 명령어에 사람이 읽을 수 있는 별명을 붙이는 것입니다.

이 게임의 어셈블리 문법은 일반적인 관례를 따르므로, 여기서 배우고 나면 대부분의 실제 CPU 어셈블리도 읽을 수 있을 것입니다.

명령어 문법은 그 명령어를 설명하는 줄임말인 **니모닉**으로 시작합니다. 그 뒤에는 **피연산자** 목록이 따라옵니다.

```asm
mov r1, 4
```

어셈블리 프로그램은 대체로 명령어를 나열한 목록입니다.

### 피연산자

#### 레지스터

위 예제에서 `r1`은 생성된 기계어에서 `1`로 바뀝니다.

#### 숫자

위 예제에서 `4`는 기계어에 그대로 들어갑니다.

#### 레이블

점프 명령어에서는 보통 생성된 기계어 안의 오프셋을 참조하고 싶을 것입니다. 레이블을 사용하면 이런 오프셋을 자동으로 계산할 수 있습니다.

```asm
jmp my_label
...
my_label:
```

레이블은 항상 한 줄에 이름을 쓰고, 그 뒤에 콜론을 붙여 선언합니다.

### 기타 기능

#### 주석

같은 줄에서 `;` 뒤에 오는 내용은 모두 주석으로 간주되어 어셈블러가 무시합니다.

```asm
mov r1, 123 ; 123을 레지스터 1에 옮김
```

#### 원시 데이터

어셈블된 명령어 사이에 데이터를 직접 끼워 넣을 수 있습니다.

```asm
U8 123
```

여기서는 바이트 `123`을 넣습니다. `U8`은 **부호 없는 8비트 값**을 뜻하며, 어셈블러는 `U16`, `U32`, `U64`도 지원합니다.

ASCII 문자의 값을 넣을 수도 있습니다.

```asm
"Hello"
```

#### 별칭: `const`

레지스터나 다른 종류의 피연산자에 새 이름을 붙일 수 있습니다.

```asm
const ROTATION = r0
```

이 예제에서 `ROTATION`은 `r0`의 또 다른 이름이 됩니다. 레지스터에 이름을 붙이면 코드를 읽기 쉬워집니다.

#### 섹션

`@` 뒤에 주소를 쓰면 어셈블러가 그 주소에 도달할 때까지 `0`을 채워 넣습니다.

```asm
@0x800
```

#### 다른 파일 포함: `include`

다른 어셈블리 파일을 포함할 수 있습니다. 예를 들어 상위 폴더의 `std_lib.asm`을 포함하려면 다음과 같이 씁니다.

```asm
include ../std_lib
```

다른 어셈블리 파일을 포함하면 그 파일의 어셈블 결과가 `include` 위치에 삽입됩니다.

포함된 파일에서 정의한 레이블과 상수도 사용할 수 있습니다. 다만 그 파일에서 `pub` 키워드를 앞에 붙여 공개한 것이어야 합니다.

```asm
pub print:
```

공개된 이름이나 레이블에 접근하려면 이름 앞에 파일 이름과 점을 붙입니다.

```asm
jmp std_lib.print
```

이를 이용하면 어느 레벨에서든 호출할 수 있는 함수 라이브러리를 만들 수 있습니다. 라이브러리 파일을 레벨들의 상위 폴더에 두고, 각 함수에 해당하는 레이블을 공개하기만 하면 됩니다.

## 언어 만들기

### 개요

다음은 간단한 어셈블리 정의의 예입니다.

```text
[fields]
register
r0 000
r1 001
r2 010
r3 011

[instructions]
mov %a(register), %b(register)
00aaabbb
# %b 의 값을 %a 로 옮긴다

mov %a(register), %b:U8(immediate)
01000aaa bbbbbbbb
# %b 의 바이트를 %a 로 옮긴다

jmp %a(label)
10000000 aaaaaaaa
# %a 로 점프한다
```

정의가 `[fields]`와 `[instructions]` 두 구역으로 나뉜 것에 주목하세요.

### `[fields]` 구역

필드를 쓰면 비트 패턴에 이름을 붙일 수 있습니다. 보통 레지스터에 씁니다. 자세한 내용은 [필드](#필드)를 참고하세요.

### `[instructions]` 구역

명령어 정의는 **구문 줄**, **기계어 줄**, **설명 줄**로 이루어집니다.

```text
mov %a(register), %b(register)
00aaabbb
# %b 의 값을 %a 로 옮긴다
```

자신이 만든 언어로 어셈블리 명령어를 입력하면, 어셈블러가 이 정의 목록을 훑어 처음으로 일치하는 구문을 찾아 그에 해당하는 기계어를 만들어 냅니다.

#### 구문 줄

구문 줄은 고정된 문자열과 피연산자가 섞인 형태입니다.

피연산자는 언제나 `%`로 시작하고, 그 뒤에 다른 줄에서 그것을 가리킬 이름이 옵니다. 이름 다음에는 피연산자 필드가 오는데, `label`, `immediate`, 또는 `[fields]` 구역에서 직접 정의한 필드가 될 수 있습니다.

#### 기계어 줄

비트 필드 줄에는 `0`이나 `1`을 쓰거나, 구문 줄에 정의한 피연산자 이름의 첫 글자를 씁니다.

`0`과 `1`은 그대로 해석되고, 피연산자 글자는 해당 피연산자 값의 이진 자릿수를 하나씩 가져다 씁니다.

#### 설명 줄

설명은 어셈블러 동작에는 아무 영향이 없고, 순전히 문서화를 위한 것입니다.

더 고급 기능은 [명령어](#명령어)를 참고하세요.

### 그 밖의 구역

`[fields]`와 `[instructions]` 외에도 선택적으로 쓸 수 있는 구역이 두 개 더 있습니다.

- [`[settings]`](#설정)
- [`[patterns]`](#패턴)

## 명령어

### 개요

[언어 만들기](#언어-만들기)는 기본적인 명령어 정의를 설명합니다. 이 항목에서는 더 고급 기능을 다룹니다.

명령어 정의는 다음 줄들로 이루어집니다.

1. 구문
2. 가상 피연산자 — 선택 사항
3. 단언 — 선택 사항
4. 기계어
5. 설명

```text
jmp %offset(label)
%high_bits = %offset / 4
assert(%offset % 4 == 0, "4바이트 정렬된 주소로만 점프할 수 있습니다")
01 hhhhhh
# %offset 으로 점프한다
```

### 구문

구문은 **리터럴**과 **피연산자**를 **공백**으로 구분해 나열한 것입니다.

#### 리터럴

위 예시에서 니모닉 `jmp`가 리터럴입니다. 피연산자가 여러 개인 명령어는 보통 `,` 리터럴로 피연산자를 구분합니다.

리터럴 안에서 `%` 기호를 쓰려면 `%%`로 이스케이프하세요.

#### 피연산자

명령어 피연산자는 `%`로 시작하며, `%name(fields)` 형태로 씁니다.

- `name`: 아무 식별자나 됩니다.
- `fields`: [필드](#필드) 구역에서 만든 필드 또는 예약된 필드 하나 이상의 목록입니다. 목록은 파이프(`|`) 문자로 구분합니다.

#### 공백

공백은 탭이나 스페이스입니다.

공백 문자를 하나만 쓰면 어셈블리 언어에서 그 공백은 선택 사항이 됩니다. 대신 공백 문자 뒤에 스페이스를 하나 더 붙이면, 어셈블러는 토큰 사이에 공백을 반드시 요구합니다.

### 가상 피연산자

위 점프 예시의 아키텍처에서는 모든 명령어가 4바이트 폭이므로, 점프 목적지의 하위 두 비트는 언제나 `0`이어야 합니다.

이 하위 두 비트를 뺀 새 가상 피연산자를 다음과 같이 만들 수 있습니다.

```text
%high_bits = %offset / 4
```

기계어 정의에서는 `%offset` 대신 `%high_bits`를 씁니다. 지원하는 연산자 목록은 [연산자](#연산자)를 참고하세요.

특수 피연산자 두 개가 자동으로 정의됩니다.

| 피연산자 | 의미 |
| --- | --- |
| `$start` | 해당 명령어 바로 앞 기계어의 오프셋 |
| `$end` | 해당 명령어 바로 뒤의 오프셋 |

예를 들어 현재 명령어를 기준으로 한 상대 오프셋을 계산할 때 다음과 같이 쓸 수 있습니다.

```text
%rel_offset = %offset - $end
```

### 단언

단언을 쓰면 사용자의 실수를 검사할 수 있습니다. 위 예시에서는 4바이트 정렬된 주소로 점프하는지 확인하는 데 썼습니다.

```text
assert(%offset % 4 == 0, "4바이트 정렬된 주소로만 점프할 수 있습니다")
```

### 기계어

위 예시는 다음과 같은 기계어 구문을 씁니다.

```text
01 hhhhhh
```

여기서 `h`는 `%high_bits` 가상 피연산자를 가리킵니다. 이 구문에서는 피연산자의 비트를 언제나 그 이름의 첫 글자로 나타냅니다.

같은 것을 **비트 슬라이싱**으로 표현할 수도 있습니다.

```text
01 %offset[8:2]
```

비트 슬라이싱은 비트 필드의 일부를 고르는 표준 하드웨어 문법을 씁니다. 형태는 `[last:first]`이며, `last`와 `first` 모두 포함입니다.

비트 슬라이싱은 여러 피연산자에 쓸 수 있고, 글자 하나에 비트 하나를 대응시키는 방식과 섞어 쓸 수도 있습니다.

### 설명

설명은 어셈블러 동작에는 아무 영향이 없고, 순전히 문서화를 위한 것입니다.

## 연산자

가상 피연산자를 만들 때 쓸 수 있는 연산자는 아래와 같습니다. 예시 결과는 모두 **`%a = -30000`**을 기준으로 합니다.

### 논리 연산

| 연산자 | 설명 | 예시 | 결과 |
| --- | --- | --- | ---: |
| `!` | 논리 NOT | `!%a` | 0 |
| `&&` | 논리 AND | `%a && 7` | 1 |
| `\|\|` | 논리 OR | `%a \|\| 7` | 1 |

### 비교 연산

| 연산자 | 설명 | 예시 | 결과 |
| --- | --- | --- | ---: |
| `==` | 같음 | `%a == 7` | 0 |
| `!=` | 같지 않음 | `%a != 7` | 1 |
| `<u` | 부호 없는 작다 | `%a <u 7` | 0 |
| `<` | 부호 있는 작다 | `%a < 7` | 1 |
| `>=u` | 부호 없는 크거나 같다 | `%a >=u 7` | 1 |
| `>=` | 부호 있는 크거나 같다 | `%a >= 7` | 0 |
| `<=u` | 부호 없는 작거나 같다 | `%a <=u 7` | 0 |
| `<=` | 부호 있는 작거나 같다 | `%a <= 7` | 1 |
| `>u` | 부호 없는 크다 | `%a >u 7` | 1 |
| `>` | 부호 있는 크다 | `%a > 7` | 0 |

### 비트 연산

| 연산자 | 설명 | 예시 | 결과 |
| --- | --- | --- | ---: |
| `~` | 비트 NOT | `~%a` | 29999 |
| `&` | 비트 AND | `%a & 7` | 0 |
| `\|` | 비트 OR | `%a \| 7` | -29993 |
| `^` | 비트 XOR | `%a ^ 7` | -29993 |

### 산술 연산

| 연산자 | 설명 | 예시 | 결과 |
| --- | --- | --- | ---: |
| `+` | 덧셈 | `%a + 7` | -29993 |
| `-` | 뺄셈 | `%a - 7` | -30007 |
| `*` | 곱셈 | `%a * 7` | -210000 |
| `/u` | 부호 없는 나눗셈 | `%a /u 7` | 2635249153387074516 |
| `/` | 부호 있는 나눗셈 | `%a / 7` | -4285 |
| `%` | 나머지 | `%a % 7` | -5 |

### 시프트 연산

| 연산자 | 설명 | 예시 | 결과 |
| --- | --- | --- | ---: |
| `<<` | 논리 좌측 시프트(LSL) | `%a << 7` | -3840000 |
| `>>` | 논리 우측 시프트(LSR) | `%a >> 7` | 144115188075855637 |

별도의 부호 반전 연산자는 없습니다. 다만 `+`나 `-` 연산자에 첫 번째 피연산자가 없으면 그 자리에 기본으로 `0`이 들어가므로, 기존의 마이너스 연산자가 그 역할을 대신합니다.

## 설정

`[settings]` 구역에서는 아키텍처의 여러 설정 항목을 정의합니다.

### `name`

아키텍처의 이름입니다.

```text
name = "Architecture name"
```

### `variant`

아키텍처에 대한 추가 설명입니다.

```text
variant = "Architecture variant"
```

### `endianness`

명령어의 바이트 순서를 정합니다. 기본값은 **빅 엔디안**입니다.

```text
endianness = big
endianness = little
```

엔디안에 대한 자세한 설명은 게임 내 설명서의 `Computer concepts/Endianness` 항목에서 확인할 수 있습니다.

> RAM 컴포넌트에는 자체 엔디안 플래그가 있어서 바이트 순서를 한 번 더 뒤집을 수 있습니다. 명령어 폭이 메모리 컴포넌트의 비트 폭과 마침 같다면 간단하지만, 서로 다르면 헷갈릴 수 있습니다.

### `line_comments`

한 줄 주석의 시작을 표시하는 토큰을 지정합니다. 한 줄 주석은 지정한 토큰에서 시작해 그 줄 끝까지를 삼킵니다.

```text
line_comments = "#"
line_comments = [";", "//"]
```

기본값은 `[";", "//"]`입니다.

### `block_comments`

블록 주석의 시작과 끝을 표시하는 토큰을 지정합니다.

블록 주석은 첫 토큰에서 시작해 마지막 토큰까지 전부를 삼킵니다. 여기에는 줄바꿈은 물론 또 다른 블록 주석 시작 토큰도 포함됩니다. 따라서 블록 주석은 중첩되지 않습니다.

```text
block_comments = {"/*":"*/"}
```

기본값은 `{"/*":"*/"}`입니다.

## 패턴

`[patterns]` 구역에서는 명령어 정의의 중복을 줄이기 위한 **텍스트 치환 매크로**를 정의합니다.

패턴의 구조는 명령어와 비슷합니다.

1. 패턴 시그니처
2. 구문 치환
3. 기계어 치환

### 정의 예시

```text
[patterns]

pattern size(width, machine_code)
U{width}
00{machine_code}

[instructions]

mov_%s[size("8", "00") | size("16", "01")] %a(reg) %b(reg)
0000 %s %a %b
# %b 에서 %a 로 옮긴다
```

### 치환 결과

```text
[instructions]

mov_U8 %a(reg) %b(reg)
0000 0000 %a %b
# %b 에서 %a 로 옮긴다

mov_U16 %a(reg) %b(reg)
0000 0001 %a %b
# %b 에서 %a 로 옮긴다
```

위 예시에서는 먼저 패턴을 선언합니다. 선언은 `pattern` 키워드로 시작하고, 그 뒤에 패턴 이름과 인자 이름들이 옵니다. 그 아래 두 줄은 각각 구문 줄과 기계어 줄에 붙여 넣을 텍스트 조각입니다.

명령어 쪽에서는 변수 이름 `%s`가 구문 줄에 놓입니다. 이 예시에서 파서는 `%s`가 잡아낸 두 가지 버전을 하나씩 훑으며, 각각에 대해 새 명령어를 만들어 냅니다. 구문 줄과 기계어 조각을 붙여 넣고, 패턴 인자를 주어진 값으로 바꿔 넣습니다.

## 필드

`[fields]` 구역에서는 명령어 정의에 넣을 수 있는 여러 종류의 필드와, 그 필드가 가질 수 있는 값을 정의합니다.

### 정의 예시

```text
[fields]
register
r0 000
r1 001
r2 010
r3 011

condition
eq 00
ne 01
cs 10
hs 10
```

필드는 빈 줄로 구분합니다. 각 필드는 첫 줄의 필드 이름으로 시작하고, 그 뒤에 허용되는 값이 하나 이상 옵니다.

값은 비트 패턴이며, 한 필드 안의 모든 값은 비트 길이가 같아야 합니다.

필드는 명령어에서 다음과 같이 쓰입니다.

```asm
mov r1, r3
```

### 기본값

`aarch64` 같은 일부 아키텍처는 즉시값 앞에 선택적으로 `#`을 붙일 수 있습니다. 이는 필드로 처리할 수 있습니다. 그래서 필드 이름을 따옴표로 감쌀 수 있게 되어 있습니다.

```text
pound
"#" 0
"" 0
```

### 예약된 필드 이름

예약된 이름은 두 개입니다.

| 이름 | 의미 | 예시 |
| --- | --- | --- |
| `label` | 어셈블러 안의 레이블을 가리킵니다. | `mylabel:` |
| `immediate` | 즉시값을 가리킵니다. | `%b:U8(immediate)` |
